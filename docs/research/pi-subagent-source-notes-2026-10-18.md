## What Pi already supplies

The installed README explicitly treats subagents as something users build with extensions or separate Pi instances. It links an official **example**, rather than promising a built-in task supervisor. See `node_modules/@mariozechner/pi-coding-agent/README.md:444` and the [versioned official README](https://github.com/badlogic/pi-mono/blob/v0.67.68/packages/coding-agent/README.md).

The bundled example offers single, parallel, and chain dispatch. Each task launches a separate Pi CLI process in JSON print mode with session persistence disabled. It allows eight parallel tasks per invocation and runs four at once. Those limits belong to the example, not a universal Pi limit. Agent Markdown files select prompts, tools, and optional models; project definitions need explicit discovery scope. Sources: [versioned example README](https://github.com/badlogic/pi-mono/blob/v0.67.68/packages/coding-agent/examples/extensions/subagent/README.md), local `examples/extensions/subagent/README.md:91-97,123-142` beneath the installed package.

The process runner parses completed messages, accumulates tokens/cost/turns, forwards partial progress, and returns final assistant text plus structured details. It wires tool cancellation to SIGTERM, then attempts SIGKILL after five seconds. It does not create git worktrees or enforce a shared global budget. Its project-agent confirmation is guarded by `ctx.hasUI`, so it is unsuitable as the coordinator's authorization boundary. Source: [versioned runner](https://github.com/badlogic/pi-mono/blob/v0.67.68/packages/coding-agent/examples/extensions/subagent/index.ts); local installed `index.ts:265-267,306-379,443-476,557-633`.

Two runner details deserve independent treatment if adapting its code. It infers the executable from `process.argv[1]`, which is unsafe to assume names Pi inside an embedded coordinator. Also, `proc.killed` records signal delivery rather than confirmed exit, so the fallback check is not proof that a hung process will be forcibly terminated. These are code-review conclusions, not verified runtime failures.

## SDK mechanisms available in 0.67.68

`createAgentSession()` accepts an explicit cwd, model, auth storage, model registry, resource loader, built-in/custom tools, settings, and session manager. `SessionManager.inMemory(cwd)` keeps conversation state independent without writing a session file. Persistent child sessions can instead use separate managers and private directories. Sources: [versioned factory](https://github.com/badlogic/pi-mono/blob/v0.67.68/packages/coding-agent/src/core/sdk.ts), [session storage](https://github.com/badlogic/pi-mono/blob/v0.67.68/packages/coding-agent/src/core/session-manager.ts); local `dist/core/sdk.d.ts:11-40` and this project's `src/runtime/create-role-runtime.ts:334-349`.

`prompt()` resolves after the accepted run, including retries. A busy session requires explicit steering/follow-up behavior. Each independently running child therefore needs its own session. Subscription events cover text, tools, messages, compaction, and retry activity. A custom delegation tool can take Pi's abort signal and forward progress through its update callback. Sources: [versioned SDK guide](https://github.com/badlogic/pi-mono/blob/v0.67.68/packages/coding-agent/docs/sdk.md), [tool contract](https://github.com/badlogic/pi-mono/blob/v0.67.68/packages/coding-agent/src/core/extensions/types.ts); local `docs/sdk.md:164-300` and `dist/core/extensions/types.d.ts:298-307` beneath the installed package.

The host must implement scheduling, ownership, recursion policy, durable task identities, worktree allocation, and cross-child aggregate budgets. Pi's session API supplies the worker conversation and tools; it does not define those coordinator policies.

## Lifecycle and accounting traps

In the installed version, `AgentSession.dispose()` only disconnects listeners. It **does not stop inference or tools**. `abort()` aborts the current agent operation and waits for idle, while compaction and branch summaries have separate cancellation APIs. Reuse this project's stronger `ManagedSession.abort()` lifecycle before disposal. Current main documentation describes a stronger disposal contract and should not be copied into a 0.67.68 implementation. Sources: [versioned session implementation](https://github.com/badlogic/pi-mono/blob/v0.67.68/packages/coding-agent/src/core/agent-session.ts), [current SDK guide](https://github.com/badlogic/pi-mono/blob/482c1381a00d8d00bc81697e4a980c593db6803e/packages/coding-agent/docs/sdk.md); local installed `dist/core/agent-session.js:489-492,1044-1047`; project `src/runtime/managed-session.ts:92-105`.

The installed session provides `getLastAssistantText()` and `getSessionStats()`, including token and cost totals. Read completion status as well as text: an aborted run can contain partial assistant output. Maintain a coordinator ledger from completed message usage when enforcing cumulative child budgets; a fresh or compacted conversation snapshot is not an authoritative lifetime invoice. See installed `dist/core/agent-session.js:2334-2373,2474-2495` and the versioned session implementation above. Reported cost also depends on configured model pricing.

Pi has process-global provider registrations. `ModelRegistry.refresh()` resets API/OAuth providers; custom stream registration is keyed by API. Concurrent embedded sessions should retain fixed, trusted providers and avoid dynamic refresh or custom stream replacement during active runs. This is a design constraint to test, not evidence that current A/B operation is broken. Source: [versioned model registry](https://github.com/badlogic/pi-mono/blob/v0.67.68/packages/coding-agent/src/core/model-registry.ts); installed `dist/core/model-registry.js:217-226,572-588`.

## Recommendation for this coordinator

Build a coordinator-owned delegation tool that creates separate child SDK sessions through the existing secure runtime. Keep A and B as top-level roles. Store child identity, parent role, operation, task, lifecycle, results, and usage separately from the two-role registry. Start with one level of children, bounded global concurrency, and read-only worker profiles. Children return evidence to their parent; the parent retains handoff and acceptance authority. These are proposed product decisions.

Do not install the sample extension wholesale. This repository intentionally disables general discovery and uses a private resource root, sandboxed tools, in-memory auth, constrained models, and provider capability tokens. The sample's independently discovered CLI process would need an equally strict bootstrap before it could satisfy those boundaries. Local evidence: `src/runtime/create-role-runtime.ts:162-179,198-205,226-251` and `src/security/provider-broker.ts:24-80`.

An isolated context window is not a security sandbox. Preserve the current trusted-client credential boundary for every child. The actual provider credential stays inside the broker. Child tools inherit no ability to read that credential or choose arbitrary endpoints. Create child contexts explicitly rather than cloning the entire parent conversation or auth configuration.

Start B children at one concurrent local inference request until measured against the configured LM Studio model and actual machine. Additional sessions do not establish additional local model capacity. A children require a separate aggregate request/token/cost limit across the parent operation. The existing broker supports request and output limits for the smoke-test path, but ordinary role sessions currently use only the model allowlist and timeout. Extending that policy is implementation work, not a feature Pi adds automatically. Local evidence: `src/runtime/create-role-runtime.ts:176-178`, `src/security/provider-broker.ts:24-33,59-74`.

Acceptance should prove concurrent child separation, output/status accounting, recursive delegation rejection, cancellation of running and queued tasks, no child work after parent stop, isolated tool access, dummy-secret non-disclosure, and provider-budget enforcement. Write-capable children should follow only after explicit worktree ownership and merge/conflict handling exist. Research alone does not validate local inference throughput or cancellation under provider load.
