## SDK and model/auth migration

This is an API migration across several releases, not an import-name substitution. The 0.80.8 change replaced SDK `authStorage`/`modelRegistry` configuration with async `ModelRuntime`. `AuthStorage` is no longer a public export. `ModelRuntime.create()` accepts a pi-ai `CredentialStore`; `setRuntimeApiKey()` is asynchronous. `ModelRegistry` survives as a synchronous extension facade constructed from an existing `ModelRuntime`, not via the old `inMemory(AuthStorage)` factory. Source: [coding-agent changelog](https://github.com/earendil-works/pi/blob/v1.3.0/packages/coding-agent/CHANGELOG.md), [model runtime](https://github.com/earendil-works/pi/blob/v1.3.0/packages/coding-agent/src/core/model-runtime.ts), [registry facade](https://github.com/earendil-works/pi/blob/v1.3.0/packages/coding-agent/src/core/model-registry.ts).

The public direct `new AgentSession(config)` constructor remains supported. Its config requires `modelRuntime` and retains `baseToolsOverride`, `initialActiveToolNames`, custom tools, session/settings/resource managers, and scoped models. The host can therefore preserve its own Agent, stream function, isolated tool implementations, and broker policy. Inspect the constructor's installed request/context/boundary hooks when adapting redaction and supervision; it now wraps several Agent hooks. Source: [AgentSession config and constructor](https://github.com/earendil-works/pi/blob/v1.3.0/packages/coding-agent/src/core/agent-session.ts#L249-L303), [published declaration](https://unpkg.com/@earendil-works/pi-coding-agent@1.3.0/dist/core/agent-session.d.ts).

The high-level SDK's `tools` option is now an array of **tool-name strings/patterns**, not an array of executable Tool instances. Keep trusted executable tools in `baseToolsOverride` or properly defined custom tools; do not accidentally fall back to built-in read/bash/edit/write. The SDK examples and declarations use the canonical `typebox` API. Source: [SDK factory](https://github.com/earendil-works/pi/blob/v1.3.0/packages/coding-agent/src/core/sdk.ts), [tool example](https://github.com/earendil-works/pi/blob/v1.3.0/packages/coding-agent/examples/sdk/05-tools.ts).

Old pi-ai global functions moved from the root to `/compat`. New instance-based `Models`/provider factories are the preferred APIs. A compatibility import is a deliberate migration choice with global behavior to test, not a silent name replacement. The synchronous bundled catalog is available through `@earendil-works/pi-ai/providers/all`, including `getBuiltinModels()` and `getBuiltinModel()`. Use metadata-only catalog access for synchronous model-picker/setup/doctor callers; keep authentication and runtime creation asynchronous and separate. Sources: [pi-ai exports](https://github.com/earendil-works/pi/blob/v1.3.0/packages/ai/package.json), [catalog API](https://github.com/earendil-works/pi/blob/v1.3.0/packages/ai/src/providers/all.ts), [Models implementation](https://github.com/earendil-works/pi/blob/v1.3.0/packages/ai/src/models.ts).

## Security defaults that need explicit treatment

`ModelRuntime.create()` defaults to file-backed credentials and models configuration. A secure construction should explicitly supply an in-memory `CredentialStore`, `modelsPath:null`, `refreshOnCreate:false`, and `allowModelNetwork:false`, then register only trusted inference behavior and broker capabilities. These options avoid default file/config/catalog initialization but do not themselves establish endpoint confinement. The runtime still contains built-in providers, and its underlying default auth context can inspect ambient environment/files. Preserve the host's fixed model/provider/endpoint guards and broker-only request path. Sources: [runtime creation](https://github.com/earendil-works/pi/blob/v1.3.0/packages/coding-agent/src/core/model-runtime.ts#L207-L257), [credential-store interface](https://github.com/earendil-works/pi/blob/v1.3.0/packages/ai/src/auth/types.ts), [default auth context](https://github.com/earendil-works/pi/blob/v1.3.0/packages/ai/src/auth/context.ts).

`allowModelNetwork:false` controls creation-time catalog refresh only. A later `refresh()` without `allowNetwork:false` derives permission from whether `PI_OFFLINE` was absent when the runtime was created. Do not describe this option as a universal network kill switch. Restrict or wrap all later refresh/catalog paths, and prove allowed network destinations with deterministic tests. Source: [runtime refresh](https://github.com/earendil-works/pi/blob/v1.3.0/packages/coding-agent/src/core/model-runtime.ts).

The CLI automatically loads native MCP, codemode, and tool-search extensions; SDK sessions do not. Keep the existing custom MCP bridge and disabled executable discovery. Do not register those native factories during this upgrade. `codemode.mode` accepts only `on` or `only`, so **`codemode:{mode:"off"}` is invalid**. Absence of the factory plus tool exclusion is how this embedding keeps it disabled. Sources: [SDK built-ins distinction](https://github.com/earendil-works/pi/blob/v1.3.0/packages/coding-agent/docs/sdk.md#codemode-mcp), [settings schema](https://github.com/earendil-works/pi/blob/v1.3.0/packages/coding-agent/src/core/settings-schema.ts).

For the direct constructor, keep `usesDefaultTools:false` and explicit trusted `initialActiveToolNames`/`allowedToolNames`. An important exception allows registered MCP tools to remain reachable when an allowlist contains no `mcp__` entries. Exclude `mcp__*`, `codemode`, and `tool_search` if native tools must remain unavailable. Keep the approved custom MCP names allowed separately. With `usesDefaultTools:true`, persisted system-message tool declarations restore the active loadout, including pending tools that register later. Test malicious/old persisted activation against role permissions. Source: [tool restoration and filtering](https://github.com/earendil-works/pi/blob/v1.3.0/packages/coding-agent/src/core/agent-session.ts).

New defaults include `cacheWarming:"streaming"`, `enableInstallTelemetry:true`, and `enableAnalytics:false`. Explicitly use `cacheWarming:"off"`, disable both telemetry settings, and omit the optional direct-constructor cache warmer. The high-level factory creates a cache warmer, which can generate additional provider work if enabled. The separate pi-telemetry library supplies explicit vendor-neutral contexts and has no exporter dependencies; its presence is not evidence that SDK use sends analytics. Sources: [settings defaults](https://github.com/earendil-works/pi/blob/v1.3.0/packages/coding-agent/src/core/settings-defaults.ts), [cache-warmer construction](https://github.com/earendil-works/pi/blob/v1.3.0/packages/coding-agent/src/core/sdk.ts), [telemetry library](https://github.com/earendil-works/pi/blob/v1.3.0/packages/telemetry/src/index.ts), [telemetry manifest](https://github.com/earendil-works/pi/blob/v1.3.0/packages/telemetry/package.json).

New `ModelRuntime` provider collections are instance-owned. The `/compat` API still has global registration facilities, and the session still imports compatibility helpers. Avoid claiming that changing package names eliminates all shared provider state. Prove concurrent A/B configuration, compaction, runtime replacement, and refresh cannot substitute another role's broker/model. Sources: [Models implementation](https://github.com/earendil-works/pi/blob/v1.3.0/packages/ai/src/models.ts), [compat entry](https://github.com/earendil-works/pi/blob/v1.3.0/packages/ai/src/compat.ts).

## Lifecycle, history, and terminal compatibility

Agent async subscriptions remain awaited in subscription order and receive the active abort signal. This supports the coordinator's awaited ten-turn supervision hook. `agent_end` ends a low-level run; it is not a promise that session recovery/queued work has finished. The new outer `agent_settled` event provides that distinction. Audit the current ManagedSession's `agent_end`/compaction bookkeeping rather than blindly keeping or replacing it. Sources: [Agent subscriptions](https://github.com/earendil-works/pi/blob/v1.3.0/packages/agent/src/agent.ts), [session lifecycle events](https://github.com/earendil-works/pi/blob/v1.3.0/packages/coding-agent/src/core/agent-session.ts), [SDK lifecycle guidance](https://github.com/earendil-works/pi/blob/v1.3.0/packages/coding-agent/docs/sdk.md).

In 1.3.0, synchronous `dispose()` initiates cancellation of retry, compaction, branch summaries, bash, and agent work, invalidates extension contexts, and clears listeners. It still returns void and is not proof that work has drained. Await explicit abort/idle/pending cleanup before reporting cancellation complete or releasing broker resources. This differs materially from 0.67.68's listener-only dispose. Source: [target disposal implementation](https://github.com/earendil-works/pi/blob/v1.3.0/packages/coding-agent/src/core/agent-session.ts).

The canonical transcript now carries system messages and tool declarations. System-prompt state is read-only; the SessionManager projection is authoritative for finalized model context. A manual assignment to `agent.state.messages` is not a replacement for restoring the manager. Any repository schemas that assume only user/assistant/toolResult messages require review. Sources: [agent transcript contract](https://github.com/earendil-works/pi/blob/v1.3.0/packages/agent/src/types.ts), [session projection](https://github.com/earendil-works/pi/blob/v1.3.0/packages/coding-agent/src/core/session-manager.ts).

Both installed 0.67.68 and target 1.3.0 have `CURRENT_SESSION_VERSION = 3`. Target still exports `migrateSessionEntries()` and supports v1/v2 migrations. The unchanged number does not establish semantic or downgrade compatibility: target adds system/tool-declaration and compaction-system state. Test copied existing histories and archive import/export, preserve originals before any target writer opens them, and use a separate migration-test session root. Source: [target session manager](https://github.com/earendil-works/pi/blob/v1.3.0/packages/coding-agent/src/core/session-manager.ts#L41), local installed `node_modules/@mariozechner/pi-coding-agent/dist/core/session-manager.js:8`.

`SettingsManager.inMemory(initial)` now seeds its backing storage before calling `fromStorage()`. The custom seeded Map workaround in current `create-role-runtime.ts` may be removable after proving reload retains security settings. ResourceLoader reload is still part of the lifecycle. Source: [target settings manager](https://github.com/earendil-works/pi/blob/v1.3.0/packages/coding-agent/src/core/settings-manager.ts).

TUI migration requires behavioral verification. New Terminal implementations must supply `setProgramStatus()`, possibly as a no-op. Cursor rendering now uses zero-width APC markers resolved by TUI; standalone render tests must strip terminal sequences properly. Terminal-color query APIs changed, as did Home/End behavior and fullscreen scrolling/mouse handling. Preserve the app's input ownership, retained history, resize, cancellation, and plain-mode behavior with actual PTY checks. Source: [TUI changelog](https://github.com/earendil-works/pi/blob/v1.3.0/packages/tui/CHANGELOG.md).

Streams now require `AssistantMessageEventStream`, not a hand-written compatible EventStream subclass. Deterministic provider fixtures may need to use the official stream factory. New assistant/tool events include optional duration metadata, and malformed final tool arguments fail validation rather than silently running partial arguments. These are targeted fixture/telemetry/validation review points. Source: [pi-ai changelog](https://github.com/earendil-works/pi/blob/v1.3.0/packages/ai/CHANGELOG.md), [agent changelog](https://github.com/earendil-works/pi/blob/v1.3.0/packages/agent/CHANGELOG.md).

## Planning implication

Treat the upgrade as one coherent runtime migration, with dependency, model/auth, tool/schema, lifecycle/history, and terminal gates. Keep the subagent feature outside this change. Pin the selected Pi family and compatible TypeBox version, remove legacy imports/packages after migrating callers, prove dummy-secret isolation before credential-backed use, and rebuild the trusted installation only after the reviewed candidate passes. Recheck release tags when implementation starts; a newer stable requires a new compatibility delta rather than silently changing this target.

This note records source-derived expectations. It does not claim that the target compiles with this repository, passes its security suite, reads its real histories correctly, or runs its terminal successfully. Those remain implementation acceptance evidence.
